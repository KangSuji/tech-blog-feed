# 기술 블로그 모아보기

여러 회사 기술 블로그의 새 글을 RSS로 모아 한곳에서 보여 주는 웹 서비스입니다.
태그·블로그별로 걸러 보고, 나중에 읽을 글을 저장할 수 있습니다.

## 프로젝트 개요

### 만드는 이유

기술 블로그는 회사마다 흩어져 있어서 새 글을 챙겨 보기 어렵습니다. 이 서비스는 로그인 없이 바로 열어서 최신 글을 훑어보고, 관심 있는 글만 원문으로 넘어가 읽는 흐름을 목표로 합니다.

기능 개수보다 **작게 배포하고 실제 사용 데이터와 피드백으로 자주 고치는 과정**을 기록하는 데 중점을 둡니다.

### 첫 배포(MVP) 범위

1. **피드 보기**: 최신순 글 목록(제목, 블로그, 작성일, 요약), 무한 스크롤
2. **걸러 보기**: 태그·블로그 필터, 키워드 검색
3. **저장하기**: 북마크와 "읽음" 표시(localStorage, 로그인 불필요)
4. **원문 이동**: 클릭 시 원문으로 이동, 클릭 수 집계

본문 전체는 저장하거나 표시하지 않습니다. 제목, 요약, 작성일, 원문 링크만 사용합니다.

### 기술 스택

| 영역           | 선택                             | 이유                                                                            |
| -------------- | -------------------------------- | ------------------------------------------------------------------------------- |
| 프레임워크     | Next.js (App Router), TypeScript | 서버 컴포넌트와 미리 생성한 페이지로 첫 화면을 빠르게 보여 주고 검색엔진에 노출 |
| 스타일         | Tailwind CSS                     | 별도 CSS 파일 없이 빠르게 화면을 만들고 고치기 위해                             |
| 서버 상태      | TanStack Query                   | 무한 스크롤, 검색 결과 캐싱                                                     |
| 화면 상태      | URL 쿼리 파라미터                | 필터·검색 결과를 링크로 공유할 수 있도록                                        |
| DB             | Supabase (PostgreSQL)            | 백엔드 서버를 직접 만들지 않고 DB·권한 관리를 맡기기 위해                       |
| RSS 파싱       | rss-parser                       | RSS 2.0과 Atom을 같은 형태로 읽기 위해                                          |
| 배포·예약 작업 | Vercel, Vercel Cron              | 1시간마다 피드 수집                                                             |
| 분석           | PostHog, Vercel Speed Insights   | 사용 이벤트와 성능 지표(LCP, INP) 측정                                          |

### 구조

```
기술 블로그 RSS ──▶ 수집 작업 (Vercel Cron, 1시간마다) ──▶ Supabase DB
                                                               │ 글 조회
PostHog 분석 ◀── 브라우저 (TanStack Query) ◀── Next.js 서버 (미리 생성한 페이지, Route Handler)
```

#### 블로그 선정과 피드 확인

- 회사 기술 블로그 12곳(수집 대상 11곳)의 피드 주소를 찾고, 각 피드에 제목·링크·작성일·요약이 있는지 직접 확인했습니다.
- 확인하면서 발견한 점:
  - 우아한형제들, 무신사, 잡코리아 등 여러 곳이 `content:encoded`에 **본문 전체**를 담아 보냅니다. → 본문은 저장하지 않고 요약만 저장하기로 했습니다.
  - 잡코리아, 백팩커스(Medium), 무신사 피드에는 요약(`description`)이 없고 본문만 있습니다. → 본문 앞 150자만 잘라 요약으로 씁니다.
  - 카카오페이 피드는 주소는 열리지만 글 항목이 하나도 없습니다. 블로그를 Gatsby에서 Astro로 옮긴 뒤 피드가 비어 있는 것으로 보입니다. → 제외했습니다.
  - 리디와 삼쩜삼은 블로그 전체 피드에 PR 기사나 세금·생활 정보가 섞여 있습니다. → 기술 카테고리·태그 전용 피드 주소로 바꿨습니다.
  - 오늘의집 기술 블로그는 RSS 피드가 없어서 제외했습니다.

#### 프로젝트 생성

- Next.js 16, React 19, Tailwind CSS v4로 생성했습니다.
- 앱 코드는 `src/` 아래에 두어 루트의 설정 파일과 분리했습니다.

#### DB 설계 (Supabase)

- 테이블 정의와 초기 블로그 목록은 SQL 파일로 저장소에 남겼습니다. → [supabase/schema.sql](supabase/schema.sql), [supabase/seed.sql](supabase/seed.sql)
- `posts.link`에 unique 제약을 걸어 **같은 글이 두 번 저장되지 않는 것을 DB가 보장**합니다.
- 두 테이블 모두 RLS를 켜고 **읽기 정책만** 두었습니다. 브라우저(공개 키)에서는 읽기만 가능하고, 쓰기는 서버의 수집 코드(secret key)만 할 수 있습니다.

#### 수집 코드

`GET /api/collect`를 호출하면 등록된 블로그의 피드를 모두 읽어 새 글만 `posts`에 저장하고, 블로그별 결과를 JSON으로 돌려줍니다.

| 파일 | 역할 |
| --- | --- |
| [src/app/api/collect/route.ts](src/app/api/collect/route.ts) | 수집 실행: 블로그 조회 → 피드 읽기 → 저장 → 결과 응답 |
| [src/lib/feeds.ts](src/lib/feeds.ts) | 피드 글 하나를 `posts` 행 하나로 바꾸는 변환 함수 |
| [src/lib/supabase/admin.ts](src/lib/supabase/admin.ts) | secret key로 만든 Supabase 클라이언트 (서버 전용) |

선택 이유:

- **Route Handler**: 수집은 Vercel Cron이 HTTP URL을 호출하는 방식으로 실행합니다. Server Action은 화면의 폼·버튼에서 호출하는 용도라서 외부 스케줄러가 부를 수 없습니다.
- **`Promise.allSettled`**: 피드들은 서로 독립적이라, 한 곳이 실패해도 나머지는 저장되어야 합니다. `Promise.all`은 하나만 실패해도 전체가 실패합니다.
- **`upsert` + `ignoreDuplicates`**: 이미 있는 링크는 덮어쓰지 않고 건너뜁니다(`on conflict (link) do nothing`). 새로 들어간 행만 돌려받아 블로그별 새 글 수를 셉니다.
- **`server-only`**: secret key는 RLS를 무시하는 관리자 키라서, 클라이언트 코드에서 이 파일을 import하면 빌드가 실패하게 막았습니다.

요약 처리 규칙:

1. `description`에서 만든 요약을 쓰고, 없으면 본문(`content:encoded`)에서 태그를 지운 텍스트를 씁니다.
2. 줄바꿈·연속 공백을 공백 하나로 바꿉니다.
3. 비어 있거나 `…` 한 글자뿐이면 요약 없음(`null`)으로 저장합니다. (뱅크샐러드 82개 글 중 12개가 이 경우였습니다.)
4. 150자를 넘으면 잘라서 `…`를 붙입니다.

결과:

- 9곳에서 글 498개를 저장했습니다.
- 같은 수집을 한 번 더 실행하면 모든 블로그의 새 글 수가 0으로 나와, 중복 저장이 막히는 것을 확인했습니다.
- 요약이 `…`인 글 0개, 요약 최대 길이 151자(150자 + `…`)로 요약 규칙이 적용된 것을 확인했습니다.

수집하면서 발견한 점:

- **리디, 우아한형제들은 403으로 차단됩니다.** 같은 주소를 `curl`로 요청하면 정상이고 Node.js에서 요청할 때만 막힙니다. 두 사이트 모두 Cloudflare가 요청 방식을 보고 봇을 차단하는 것으로 보입니다. 차단을 우회하지 않고, 배포 환경(Vercel)에서 다시 확인한 뒤 계속 막히면 제외할 예정입니다.
- **뱅크샐러드만 `ERR_INVALID_PROTOCOL` 에러가 났습니다.** 원인은 시드 데이터의 피드 주소 앞에 붙은 탭 문자였습니다. rss-parser는 주소가 `https`로 시작하는지를 보고 요청 방식을 고르는데, 탭 때문에 `http` 방식으로 요청했습니다. DB 값과 seed.sql을 함께 고쳤습니다.
